# AGENTS.md — operating rules for this repository

`README.md` is the **product**: a curated list a reader can scan. It carries entries, measured numbers, and the claims those numbers rest on. Everything about *how the list is produced, cleaned, and refreshed* lives here, not there. If a sentence explains our procedure rather than helps a reader choose a project, it belongs in this file.

`CONTRIBUTING.md` is the short version for human PR authors. This file is the full operational spec for anyone (agent or human) maintaining the corpus. Two procedures have been split out because each is large enough to need its own file: the monthly look-back over entered repositories — its triggers, output format and the work an agent may do per flagged row — is in **`RECHECK.md`**; the leads that are not entries yet, what has been verified about each and what the filing decision would be, are in **`WATCHLIST.md`**. This file keeps only those pointers, the tests the two files cite, and the facts they turn up.

Things that were removed from the README on purpose and must not creep back:

- The measurement legend (which endpoint, which date, the 14,217-topic-repository figure, the 572-row corpus). One reader-facing data-provenance line stays in the README; everything else is this file.
- Census coverage and its holes (the rate-killed tokens, the under-counted "compatibility layer" vocabulary, the unmeasurability of Douyin).
- The argument for the axis ("type is the only axis…"). The section names themselves stay in the README; the reasoning lives in `## Filing axis` here.
- Why a claim is `⚠` (the mark and the claim stay; the meta-commentary about how it was checked goes in `Sourcing ledger` below).

## Admission: the three tests every entry has to pass

`## Filing axis` below decides **where** a project sits. This section decides whether it sits here at all. Admission is one rule with three parts, each answerable from the repository itself, in one pass, at intake:

- **A1 — Provenance, in two halves.** There has to **be** something reconstructed — a program, engine, format, platform or behaviour the rights holder actually shipped — and it has to have been arrived at **without the rights holder's source**: from a shipped binary, the original data or archives, or behaviour observed over a wire or through a save file. A project that builds on source the vendor or the author published itself fails the second half, because the thing we would count as a reconstruction is the thing that was handed over; a ROM hack, a fan level, a randomizer or an original game fails the first, because nothing shipped was taken apart.
- **A2 — Claim.** The repository's **own README or description states one of the four method shapes** — byte-matching decompilation or disassembly, clean-room engine reimplementation, format/protocol/driver/API reimplementation, port or static recompilation of the original binary (including a compatibility patch). Read it at write time and keep the sentence; an inference by the reviewer is not a claim, and neither is a search result's title.
- **A3 — Artifact.** The linked repository **contains the reconstructed code**. A compatibility database, a showcase page, a video, an installer, a run-recipe document, a mod loader, or a docs tree whose recompiler lives in a submodule is not an entry.

Six classes fail, and the class plus the test letter is what a rejection cites — never merit, never the star count:

| Does not enter | Fails | Because |
| --- | --- | --- |
| Source released by the rights holder, then compiled, continued or ported (`source-sdk-2013`, C&C Generals, Descent 3, Flash Player, `Werkkzeug3`, `TerryCavanagh/VVVVVV`, the `ioquake`/`yquake2`/`vkQuake`/`Quake3e`/`ironwail` family, `chocolate-doom`, `dhewm3`, `RBDOOM-3-BFG`, `JACoders/OpenJK`, `TheSuperHackers/GeneralsGameCode`, `Warzone2100`, `arx/ArxLibertatis`, `kripken/BananaBread`, `inolen/quakejs`) | **A1** | The code was given, so the artifact contains no reconstruction of it. |
| Instrumentation: debuggers, decompilers, hex editors, MCP bridges, dumpers, launchers, other lists (`ran-j/PS2Recomp`, `tgeorgiadis/quiver-launcher`, `michelpereira/awesome-open-source-games`) | **A3** | The product is a tool or a list, not an outcome; the boundary lists are named under Related lists. |
| Runtime read/write of another process's state — trainers and memory editors | **A3** | The class and its section were deleted 2026-10-17 and M5 retired; the record is in `## Takedown and legal record`. |
| Original or fan content, ROM hacks, new levels, randomizers, multiplayer mods on somebody else's port (`space-station-14`, `freedoom`, `celeste64`, `Rangi42/polishedcrystal`, `coop-deluxe/sm64coopdx`, `zsrtp/Randomizer`) | **A1** | Nothing shipped was reconstructed; new work was authored on top of the shipped work. |
| A fork of a repository already entered (`sm64-port/sm64-port`, `Keriew/augustus`, `Supermedo/bloodborne_pc`, `d07RiV/diabloweb`, `HayatoG/dusklight`) | **A3** + the single-link rule | The reader reaches the result through the one entry; the fork is prose in that paragraph. |
| A real project whose README publishes no method sentence at all | **A2** | Unprovable in one pass, so it is a lead in `WATCHLIST.md`, not an entry — and A2 is re-run the day the project states its method. |

- **What is machine-checkable and what is not.** `scripts/quality.py` answers A3 (404, `exclude` for no code or no README) and measures the E1–E4 completion evidence, but **no E-class or flag means "vendor source" or "the original binaries are in this tree"** — the A1 read is of the credits section, the README's own provenance sentences, and the repository root listing. `JoppieToppie/Galaxy-on-Fire-2-Unity-Remake` is the worked case: the gate returned `conditional` on its CI alone while `Reference/binaries/` held the shipped ARM library and a modded APK.
- **Nothing in this file rules on what a linked repository's tree contains.** The only boundary rule we have is 「No game files, ROMs, cracked binaries, or keys anywhere in this repo」, and it constrains *our* tree; it was cited once as a reason to hold an entry and that citation was wrong, because a link to somebody else's repository is not our copy of their files. Whether a binary inside a third-party repository really is the rights holder's build cannot be determined from the outside, so on 2026-10-17 the owner declined to adopt a proposed rule that would have excluded such repositories (**「不加这条规则，我们没有能力判断仓库里放的是不是厂商的程序」**) and none was written. A1 still asks only *how the project obtained what it reconstructed*; where the project keeps its reference material is not an admission test, and it is not a recheck trigger either (see `RECHECK.md`).
- **Failing admission is not a quality judgement.** A vendor-source port can be excellent software and still not be a reconstruction; `soyrochus/mucrab` and `storytold/wordcraft` clear A1 on a behaviour claim with no binary at all. Write the test the project failed, in the rejection, and nothing else.
- **Stars, push age, license and `ai_flag` are not admission tests.** A ★×age band orders *attention* and is written into a line as a status phrase when a project has gone quiet; a license gap is stated in the line; how a result was produced is an attribute. None of them opens or closes the door — A1–A3 do. That is why a numeric bar cannot be used to drop the source-port class: those repositories are large and active by construction.

## Filing axis: kind of software, then platform

Sections are the **kind of software that was reconstructed**, because that is the question a scanner is asking: is there a game here I can play, and is there a component here I can reuse. These are **filing** tests, applied only after A1–A3 pass — they say which section, not whether the project enters.

| Section                                | Filing test                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `## Games`                             | The artifact **is a shipped game** (or an engine that plays them). Second level = the **original platform**.        |
| `## Applications`                      | The artifact is a non-game program: a player runtime, an office application, a desktop utility.                      |
| `## Runtimes and compatibility layers` | The artifact is the platform the program expects: an API, firmware interface, managed runtime, emulator, or the patch that unblocks a title on a new host. |
| `## Formats, file systems and protocols` | The artifact is a data structure or a wire protocol reimplemented from observation.                                |

Four type sections since 2026-10-17: the fifth, `## Trainers and modifiers`, was deleted with its four entries, so a repository whose artifact reads or writes another process's memory at runtime has no filing home and fails A3, and does not enter. The removed class and its legal record are under `## Takedown and legal record` below.

`Games` second levels: `### Nintendo`, `### Sony PlayStation`, `### Microsoft Xbox and Xbox 360`, `### MS-DOS, Windows and Macintosh`, `### Mobile`, keyed on the platform the original software ran on. Add a platform level only when an entered title's original platform is not covered by one that exists — the Xbox level was created on 2026-10-16 for three titles, `### Mobile` on 2026-10-17 for one (`Galaxy on Fire 2`, Android and iOS), neither as a placeholder. A destination belongs in the entry line, never in a heading (`PS4 → Windows and Linux`).

Precedents set while re-filing, follow them for new entries:

- `jhaizhou-ops/d2r-mobile` is **Games / Nintendo** (Switch), not Runtimes: it reimplements a platform surface, but the artifact the reader gets is Diablo II running on a Mac.
- `JoppieToppie/Galaxy-on-Fire-2-Unity-Remake` is **Games / Mobile**, keyed on Android and iOS as the platform the original ran on — the same test that puts a Switch→iOS recompile under Nintendo rather than here. Its line is the one place in the README that says the reconstruction ships the original assets, because it does; `## Games`' intro is worded to allow that one entry rather than to describe the corpus. Whether a linked repository holds vendor binaries is not a thing this file rules on (see `## Admission`).
- `yuzuatri/Sengoku-Rance-Deck-Fix` is **Runtimes and compatibility layers** even though it patches one game: what was reconstructed is the missing codepage behaviour, and it sits next to the Wine paragraph that explains it.
- `azahar-emu/azahar` is **Runtimes** (it runs games but is not a game); `ruffle-rs/ruffle`, `storytold/wordcraft`, `soyrochus/mucrab` are **Applications**; `kichikuou/xsys35c` is **Formats** (a bytecode format's compiler and decompiler), while `kichikuou/xsystem4` is **Games** (it plays AliceSoft titles).
- The one ledger section left at the bottom of the README (`Related lists`) is a ledger, not a type section. A repository mentioned there is linked once, in its type section, and written as plain text here. `Takedown and licence history` was the other ledger until 2026-10-17; its content is now `## Takedown and legal record` in this file.

## Method labels: four live internal ids, written inline

M1–M5 are **internal ids for the method label written into each entry line**; M5 is retired (see the table below), so four are in use. They are no longer the filing axis — `## Filing axis` above is — and the codes themselves never appear in a README. Since 2026-10-16 there is also no README paragraph set that groups repositories by them. Every project still has exactly one home, and that home is a type section. These must never become sections either: how a result was produced (agent, Ghidra, a person), how it attracted attention (a short-video wave), what its license is, whether it was taken down. Those are attributes to write into the entry, or material for `## Takedown and legal record` below.

M5 — trainer and memory editing — was **retired on 2026-10-17** with the `## Trainers and modifiers` section. The id survives here so an old entry line or a note in `WATCHLIST.md` is not reinterpreted, but no repository admitted on that signal belongs in the README now.

Judge by **what the artifact is**, not by the technique used to obtain it:

| Signal in the artifact | Id | Label the README line uses |
| --- | --- | --- |
| source that diffs against / compiles byte-identical to the shipped binary; "matching bytes", "exact reconstruction" | M1 | Byte-matching decompilation and disassembly |
| a new engine or application that **consumes the original data/archives**, containing no original code | M2 | Clean-room engine reimplementation |
| a behaviour-compatible reimplementation of a format, protocol, driver or API, obtained by black-box observation / spec drafting / differential testing | M3 | Format, protocol, driver and API reimplementation |
| the original binary running somewhere it did not before — ports, static recompilations | M4 | Port and static recompilation |
| shims, patchers and compatibility fixes for one host | M4 | Compatibility patch |
| runtime read/write of another process's state | ~~M5~~ | retired 2026-10-17 with the `Trainers and modifiers` section — such a repository is not admitted by type any more |

M4 covers two README labels: use **Port and static recompilation** when the artifact moves a whole game to a new platform, **Compatibility patch** when it unblocks one title on a host it already nominally supported.

Precedents set while re-filing the list (follow them for new entries):

- Static recompilation of a console game to a new platform is **M4 / Port and static recompilation** (`gow3_pc`, `Tekken3Recomp`, `god-of-war-recomp`, `tkdr-recomp`, `TeamGDB/Yakumo`): recompilation is the means, "runs where it did not before" is the product.
- `N0zoM1z0/th04` and `N0zoM1z0/dx-ball` are **M1** on the strength of their own claims ("2,139 matching bytes", "exact reconstruction is in progress"). If a project later drops the byte-matching claim, reclassify.
- `soyrochus/mucrab` is **M3**, not M2: it reimplements an application's observed behaviour and consumes no original game data.
- `storytold/wordcraft` is **M2** and is *not* agent-RE output: it is filed clean-room on the strength of its own README, which since 2026-10-16 reads "Clean-room: built from public specifications and observation, with every asset original or openly licensed". The earlier sentence this bullet and the README line quoted ("we explicitly do not use reverse engineering… 100% clean room") is **no longer in that repository** — code search for it returns `total_count = 0` — so the README now quotes the current text; see `## Sourcing ledger`. Never label clean-room work as agent output. `sushi-shi/homm1-decomp` belongs to a different model; `Moxnatiy/OpenBattlefield2` is Ghidra work.
- Officially released source that merely got compiled is **not RE** and fails admission at **A1**; the class, the worked examples and the reason live in `## Admission` above. Do not file such a repository under a method label, and do not link it from a type section.
- Tools (debuggers, decompilers, hex editors, MCP bridges) are out of scope entirely, at **A3**; the boundary lists are named under "Related lists".

## Entry mechanics

```markdown
- [owner/repo](https://github.com/owner/repo) - Title or product, original platform → destination, method label, license if declared. ★ 1,234 · 12 forks · pushed 2026-10-15.
```

- Real examples of the shape: `- Zelda: Ocarina of Time, Nintendo 64, byte-matching decompilation.` / `- God of War III Remastered, PS4 → Windows and Linux, static recompilation of the original console binary, GPL-2.0, C++.`
- The **software type comes from the section**, so never repeat it in the line — no `**Game code**` prefix any more.
- The link must be a repository that contains code. The description starts uppercase, ends with a period, and is separated from the link by ` - `.
- A port or recompile states both ends (`PS4 → Windows and Linux`); a non-port states only the platform it came from. Platform names are the vendor's own (Nintendo 64, not "N64" on first use).
- A list item either starts with a link (an entry) or is prose in a paragraph. Analysis without a link of its own goes in a paragraph, never a bullet.
- **No hard-wrapping**: one paragraph per line, entry bullets included.
- Every URL appears **exactly once** in each README — `awesome-lint` fails on a duplicate. Where a project matters to two sections, link it in its type section and write its name as plain text (`owner/repo`) in the other; `Related lists` is plain text for that reason. That is also why the GitHub REST endpoint appears in the data-provenance line as code, not as a link.
- Keep tables narrow enough that a wide cell is not needed: a row carrying twenty names belongs in prose, and since 2026-10-16 nothing in the README is that shape.
- Entries within a section are listed **largest-first by stars as a courtesy**, not as a claim: `--apply` rewrites numbers without reordering lines, so the order goes stale by design. Never cite the ordering as data.
- `## Contents` must be the first section and must not list `Contributing`, `Footnotes`, or a licence; no `## Licence` section and no CI badge; no logo requirement unmet if you add one. Nested `###` platform levels are listed in `Contents` as sub-items.
- Do not write a measurement date that `--apply` cannot patch ("re-read from the API on 2026-10-16", "measured 2026-10-16"). The refreshed-date line is the only snapshot date in the README; a `created <date>` is a historical fact and is allowed.
- Write for a reader who is scanning a list, not for a reader of our essay: no rhetorical framings like "the class most useful to 'get my old game running here'", no "cautionary tale" / "the most instructive entry" verdicts, and no bold one-line moral at the end of a paragraph. State what the project does, what was reconstructed, and what the numbers are; leave the judgement implicit in the entry list.
- Fidelity distinctions that only our filing procedure cares about (byte-matching vs reassembles-to-ROM, for instance) stay in the entry line as two words, never in a paragraph explaining the ladder.
- The colliding name stays recorded here only: `kaixinbaba/awesome-rea` exists at 5★ and presents OpenMW / ScummVM / OpenRA / Ruffle as "rea" results, which they are not — those are decades-old projects with no agent in their history, and this list's naming paragraph is what makes that distinction. The entry was deleted from Related lists on 2026-10-16: a same-name list we rate badly is not a resource a reader needs. Recognisability beat uniqueness, and this bullet is where the collision is documented.

## Removal: the four reasons an entry leaves

An entry is deleted from **both** READMEs in one commit for exactly one of four reasons, and the reason is what the commit message names and what the paragraph absorbing its facts repeats. Nothing else removes a line.

| Reason | Read before acting | Where the record goes | What happens to the line |
| --- | --- | --- | --- |
| **Gone** — the repository 404s | `GET /repos/{owner}/{repo}` returning 404, confirmed by `verify.py links`, so it is not an anonymous-quota artefact | `## Takedown and legal record` when a notice explains it, otherwise the `## Sourcing ledger` note beside the claim it carried | deleted; the name survives as plain text with its last measured ★ and push date and the date the link was found dead |
| **Taken down** — a `github/dmca` notice names it | the notice file itself, at the path `scripts/recheck.py` prints — the filer, the date, and what the notice actually claims | `## Takedown and legal record`, which is where re3/reVC, yuzu and Citra already live | deleted, **and never replaced by a fork or a mirror**: after a takedown the result is not linkable, and citing a derivative as current is the one error this corpus has made a rule against |
| **Class no longer met** — the project now fails a test it once passed: the rights holder published the source, the artifact has become instrumentation, or its whole class was deleted (the trainers and memory editors, 2026-10-17) | the repository's own credits section and README again, plus its root listing | a row in the `## Admission` exclusion table with the test letter, and the removed class's history in `## Takedown and legal record` | deleted; the four repositories deleted with the `## Trainers and modifiers` section are listed there by name so a later reader can tell the class was removed rather than never found |
| **Claim falsified** — the sentence our line quotes is no longer in the repository, or the tree does not hold the reconstruction the line says it holds | re-read the README (a quote is re-read at write time, the `storytold/wordcraft` retraction is the worked case) **and** the root file list (which is what turned two ★-50 "rebuilds" into fabrications) | a visible retraction in `## Sourcing ledger` keeping what was wrong and why it looked right | either rewritten and kept, when the project still clears A1–A3 on what remains, or moved back to `WATCHLIST.md` as a lead |

- A `stale`, `lic` or `gone` row from `RECHECK.md` says *a line needs reading*, not *an entry is leaving*. Three of the four reasons above can only be decided by a person who has read something; the fourth, `gone`, is the only one the machine establishes on its own, and even then it costs one confirming `GET`.
- Stars, push age, licence, `archived` and how the work was produced are **not** removal reasons, for the same reason they are not admission tests. `archived` in particular is an author marking a finished reconstruction read-only, which is a completion signal written into the line, not a disqualification.
- After any removal, run `python3 scripts/check-i18n.py`: the mirror gate compares link sets and per-section entry counts, so a one-sided deletion fails it, and `awesome-lint` fails on a URL left behind in one file.


- Call `GET https://api.github.com/repos/{owner}/{repo}` and copy stars/forks/pushed from the response. Never use a search engine's number or a README badge.
- Legal claims require the filing, the notice text, or the project's own statement. Otherwise mark the sentence `⚠` and state what was actually read.
- `⚠` marks carried in the README now, each with its reason — keep them until a primary source is read:
  - **Wine GB18030 vs GBK substitution is an approximation**: reasoned from the codepage tables present in Wine 10.0 on this machine, not from a Wine source read-through.
- `⚠` marks retired when the `Takedown and licence history` and `Trainers and modifiers` sections were deleted on 2026-10-17, kept here because the research is what they rest on: **8,535 forks** removed by one DMCA notice rests on press coverage, since the `github/dmca` file path an agent supplied 404s; **WeMod did not go free** — 2026-05-01 brought a 2 h/day free cap plus a Pro subscription, and it was stated wrongly during research, so the correction is kept on purpose. Both claims are written out under `## Takedown and legal record` below, with their marks intact.
- `⚠` marks retired when the Kkrieger / Werkkzeug3 entry was deleted with the "officially released source" section on 2026-10-16, kept here because the research is what they rest on: **the authors' publication of the source is not readable from an official repository** — `Farbs/Werkkzeug3` 404s on GitHub and only `jaromil/kkrieger-werkkzeug3`, a mirror, is readable, which is why the case is excluded as vendor-released source rather than filed as a result.
- `⚠` marks retired with the short-video section on 2026-10-16, kept here because the research is what they rest on: **Tekken 7/8 "port" clips judged as emulation/cloud** — read from video titles and descriptions, never from inspecting a build; **no Douyin view counts** — `douyin.com/` and `douyin.com/search/…` return byte-identical 72,914-byte JS application shells with no server-rendered titles, so every view count we have is bilibili's.
- Negative findings are data. "No offline-trainer acquittal or non-prosecution decision found" stays recorded, with the note that the conclusion therefore rests on academic commentary (刘艳红) rather than precedent.
- Retraction kept on purpose, 2026-10-16: the `storytold/wordcraft` README line quoted its contributors saying "we explicitly do not use reverse engineering… 100% clean room". That sentence is **no longer readable in that repository** — its README's only clean-room statements are its headline ("an open-source, clean-room reimplementation of Microsoft Word, rebuilt in pure Rust") and its licence line ("Clean-room: built from public specifications and observation, with every asset original or openly licensed"), and GitHub code search for `do not use reverse engineering` in that repo returns `total_count = 0`. The line now quotes the current text. Quote a repository by re-reading it at write time, never by keeping a sentence that once looked good.
- `storytold/*` popularity is recorded **as measured, with no credibility verdict** — owner's decision 2026-10-16 (「保留，无需判断star是否可信」), so do not add one to a README. Read from `GET /repos/{owner}/{repo}` that day: `wordcraft` ★ 13,515 · 3,497 forks · 69 watchers · 735 commits · 137 contributors · created 2026-10-07 · 1,243 open issues; `photocraft` ★ 64,460 · 11,228 forks · 269 watchers · 2,429 commits · 310 contributors · created 2026-09-30 · 2,358 open issues. Star:watcher is 195.9 and 239.6 against a control band measured the same way: `scummvm/scummvm` 22.0, `vcmi/vcmi` 46.8, `OpenRA/OpenRA` 46.3, `cheat-engine/cheat-engine` 55.7. Commit cadence 80/day and 152/day. Both halves are recorded so the note is not read two ways: the ratio is not how a list this size moves, and 137 and 310 contributors are not an empty shell either. `storytold/photocraft` is **not entered** — its class test passes (own README: clean-room reimplementation of Adobe Photoshop, Rust, Apache-2.0) and it was held out because the owner chose to correct `wordcraft` rather than grow the account's presence here. If it enters later, take the method claim from its README and re-read every number.
- Never rewrite a quote from a video title, README, or filing to satisfy a spell checker. `移植自 IOS 版` stays verbatim here even though `awesome-lint` would warn about "IOS" if it appeared in a README.
- Do not guess URLs. A wrong slug is worse than a missing entry — `yuzuatri`, not `yuzatri`.
- Retract visibly: fix a wrong number in the same commit and keep the note saying what was wrong and why it looked right.
- No game files, ROMs, cracked binaries, or keys anywhere in this repo.

## Takedown and legal record: the two deleted ledger sections

Held here since 2026-10-17, when `## Takedown and licence history` and `## Trainers and modifiers` came out of both READMEs. This is the only place these claims live, so an entry line that needs one of them cites this file rather than a README paragraph. Nothing here is reader-facing product; the `⚠` marks mean the same thing they meant in the README — not read from a primary source.

**yuzu** was sued 2024-02-26 and settled for **$2.4M + a permanent injunction + source removal**; `api.github.com/repos/yuzu-emu/yuzu` → **404**, re-checked from this machine. **Citra** is likewise gone — `citra-emu/citra` → **404**.

One DMCA notice removed **8,535 forks** (yuzu derivatives). ⚠ That count comes from press coverage; the specific `github/dmca` file path an agent handed over **404s**. Treat it as reported, not as read. In 2026-08 seven further notices removed 400+ repositories (Skyline, MonoNX, yuzu derivatives), and Nintendo's notices frame the claim as **TPM circumvention under DMCA §1201**, not only copyright — that framing is what makes fork-network takedowns mechanically possible.

**re3 / reVC** (GTA III and Vice City decompilations) were DMCA'd by Take-Two in 2021-02 and the repositories are gone; no licensed successor exists, so do not link a fork as though it were current.

**Dolphin** was pulled from Steam in 2023-05 after a Nintendo DMCA; the repository is still active.

**Asahi Linux**: Hector Martin stepped down 2025-02 over maintenance pressure, **not** Apple legal; governance moved to seven maintainers. Their published copyright position ("we reverse-engineer the hardware, not the drivers") is the most reusable compliance framing in this space.

**Two of our own entries appear in `github/dmca`, read 2026-10-17 from the notices themselves** (found by `scripts/recheck.py`, which searches a shallow clone of that repository — see `RECHECK.md`, not a submodule and not committed here). `sdlpal/sdlpal` is named in `2022/08/2022-08-30-sdlpal.md`, whose complainant identifies as an SDLPAL maintainer and targets **modified builds linked against proprietary advertising SDKs** in violation of GPL-3.0 — an enforcement action against derivatives, not a claim that the reimplementation infringes; the repository is live at ★ 1,980 · 392 forks · pushed 2026-10-05. `OpenSC2K/OpenSC2K` is named in `2018/2018-07-25-EA-2.md` and, more usefully, in EA's own counter-notice `2018-11-2018-11-16-EA-CounterNotice.md`, which states that the entire OpenSC2K repository does not infringe. A third hit, `OpenRA/OpenRA`, is noise: the notice names the unrelated `KOYK/OpenRA-Tiberian-Dawn-Apolyton`. Matching the canonical `github.com/{owner}/{repo}` URL instead returns almost nothing (`github.com/yuzu-emu/yuzu` appears in **0** files while `yuzu` appears in 27), because a notice lists what was removed, which is usually a fork.

**Trainer enforcement in China**, as far as public records go: every named criminal case found is online or competitive — Jiangxi Yingtan Yujiang district court, 2024-05-06 ("AI cheat", ¥6M+ illicit turnover) under *提供侵入、非法控制计算机信息系统程序、工具罪*; the first *Honor of Kings* cheat case (2018); since 2025 Shanghai Songjiang has charged *侵犯著作权罪* instead. **No acquittal or non-prosecution decision for a purely offline single-player trainer was found**, so that distinction rests on academic commentary (刘艳红: pure-statistics cheats should not be 非法经营罪) rather than precedent. ⚠ *WeMod did **not** go free:* what took effect 2026-05-01 is a 2 h/day free cap plus a Pro subscription.

The four repositories deleted with that section, so a later reader can tell that the class was removed rather than never found: `cheat-engine/cheat-engine` (memory scanner and trainer, Windows with a Linux build, ★ 19,328 · 2,829 forks · 347 watchers · last push 2025-04-19 · Pascal), `korcankaraokcu/PINCE` (same for Linux, ★ 3,126 · 192 forks · 37 watchers · pushed 2026-09-18 · Python), `air041001/rance10-modifier` (offline modifier for AliceSoft's Rance 10, Windows, MIT, ★ 11 · 0 forks · created 2026-09-29), `nunuhara/r10-mod-system` (mod framework for the same title, Windows, C++, ★ 6 · 2 watchers · last push 2021-11-21). Numbers read 2026-10-17 by `scripts/quality.py` from `GET /repos/{owner}/{repo}`; the README had carried ★ 19,327 for Cheat Engine from the 2026-10-16 snapshot. `air041001/rance10-modifier` is the one the machine gate called `eligible` (E2, a compatibility table in its tree) and `nunuhara/r10-mod-system` the one it called `watch` (no E1–E4 signal), which is a fair picture of the pair.

## Census: coverage and its known holes

Enumeration vocabulary used to build the corpus: `reverse-engineering`, `decompilation`, `reimplementation`, `clean-room`, `engine-reimpl`, `decomp-project`, `trainer`, plus format and port tokens. Corpus: 572 raw search rows (topic enumeration + curated `repo:` batches + single-token searches) → deduplicated into the current entries.

A second channel was opened on 2026-10-16: the aggregator under `## The aggregator we are sized against` as a **slug queue**. It is enumeration, not evidence — every row it produced here was live-measured and had its own README read first (see the ≥1,000★ batch in that section), which is why 36 of its 105 ≥1,000★ slugs did not become entries.

Measured limits — treat these as open work, not as settled completeness:

- [`topic:reverse-engineering`](https://github.com/search?q=topic%3Areverse-engineering&type=repositories) returns 14,217 repositories and is overwhelmingly **tooling**, so topic enumeration alone cannot find results.
- Three planned tokens — `linux-port`, `wine-nls`, `asset-extract` — returned nothing because anonymous search is rate-limited per source IP and the run was killed mid-flight. Projects that self-describe only as "compatibility layer", "port", or "native run" are therefore **systematically under-counted**: `jhaizhou-ops/d2r-mobile` (created 2026-10-12) was missed on exactly that basis and entered the list only after a reader asked.
- No systematic census of single-title Proton/Wine patches exists yet.
- The short-video 移植 wave (抖音 / 快手 / B站 advertising ports of 战神, 街霸, 铁拳, 拳皇) was measured on 2026-10-16 and is now internal-only. Seven repositories behind it are real engineering and carry the M1 (`3s-decomp`) and M4 (`gow3_pc`, `gow3_android`, `Tekken3Recomp`, `god-of-war-recomp`, `Tekken-Tag-2-Recompiled`, `tkdr-recomp`) method labels; since the 2026-10-16 re-file they sit in `Games`, spread over the Nintendo, Sony PlayStation and MS-DOS/Windows platform subsections; the rest is (a) repack of an official build — "街霸VS铁拳 非官方移植安卓!**移植自 IOS 版**" redistributes Capcom's own iOS release, (b) emulation or cloud streaming labelled 移植, or (c) nothing at all — 「20人团队呕心沥血十天10夜移植《街霸6》手机版」 with an empty description and no SF6 reimplementation anywhere. Reach ran the wrong way: repo-naming videos drew 1,167–5,199 bilibili plays (BV1MSpz6QEJM 1,167 → BV1uNpU6CEyj 5,199), gated repacks and fabrications 7,391–26,271. No title-specific DMCA was found for any of the seven; the only platform signal was self-reported in a video title (「…视频被举报了,重新发下」, BV1dQJ66tEdZ, 2026-10-15).
- Douyin cannot be measured at all: `douyin.com/` and `douyin.com/search/…` return byte-identical 72,914-byte JS application shells with no server-rendered titles, which is why every play count above is bilibili's.
- Absence from this list is not evidence of non-existence.

## The aggregator we are sized against: `SubmitGame/awesome-decomp-games`

Read from that repository on 2026-10-16, because its scale is the first question a reader asks about a curated list and the answer is aggregation, not collecting. Created 2026-10-09, ★ 969, 39 forks, CC0-1.0, one human committer (`VibeFin`, 20 commits) plus `github-actions[bot]` (16 commits); 36 commits total. Its **first commit already carried 1,329 rated projects** — the corpus was never assembled entry by entry.

How the volume is produced: `data/games.json` (2,118 rows, 1,829 unique titles, 1,771 active / 347 inactive, 18 mods, 42 browser-playable) is the **union of 13 upstream catalogs and registries**, deduplicated by repository URL and re-measured against live GitHub data, with a ≥10-star bar (≥100 for the Quiver catalog, ≥25 for the mashups list) and a `data/dropped.json` exclusion ledger. Per-row source attribution sums above 2,118 because a project usually appears in several sources: unbaked.games 1,500 · recomp.fyi 954 · SamidyFR/Game-Decompilations 634 · CharlotteCross1998/awesome-game-decompilations 463 · Quiver Launcher 350 · radek-sprta/awesome-game-remakes 263 · portsdr.com 229 · recompiledgames.com 42 · r/decomps 34 · one X post 24 · BlueInterlude/awesome-recompilations 21 · r/recomps 14 · awesome-game-mashups 4 · manual 2. Its own scripts say the upstream numbers are only a pre-filter (`build.py` re-applies the star bar on live data), and each row carries `score`, `play_status`, `ai_flag` (266 rows) and a daily `checked_at`.

So the two lists are different artifacts and neither measures the other:

## Candidates: leads that are not yet entries

The candidate list is its own file, **`WATCHLIST.md`**, one block per lead with the same five fields every time: **Asked** (who asked, and when), **Verified** (what was read, from where, on what date), **Negative finding** (queries run and their counts, so nobody repeats or invents one), **Refused, with the test** (the A-test or filing rule each neighbouring candidate failed), and **If it appears / Filing consequence** (which section, which platform, which words the line must use). A lead never enters a README before its repository exists, has been opened, and has had its numbers read from `GET /repos/{owner}/{repo}`; until then it is a lead recorded there, not data, and nothing in it may be quoted into a README.

Two things from that file are rules for this one rather than leads, so they are restated where they apply:

- Candidates are expected to be **under-counted by the existing enumeration vocabulary**: such projects self-describe as "port", "native run" or "compatibility layer", which is precisely the vocabulary the rate-killed `linux-port` / `asset-extract` tokens failed to cover (see `## Census`).
- The console families there are the corpus's **highest-DMCA-risk material**: Nintendo's 2026-08 notices are framed as TPM circumvention under DMCA §1201, not only copyright, which is what makes a whole fork network removable at once. Record the notice text if a takedown lands, and do not cite a fork as current after one.

## Refresh automation

`scripts/verify.py` is the only place numbers are obtained. Looking back over what is already
entered is a separate procedure with its own triggers and output format: **`RECHECK.md`**.

```console
$ python3 scripts/verify.py links            # HEAD/GET every URL in both READMEs, spends no API quota
$ python3 scripts/verify.py refresh          # measure every linked repo, write scripts/snapshot-<date>.tsv
$ python3 scripts/verify.py refresh --apply  # additionally rewrite the measured tokens in both READMEs
$ python3 scripts/check-i18n.py              # English/Chinese mirror gate
$ npx --yes awesome-lint README.md           # structure gate (needs a commit, an origin, and the two topics below)
```

- `awesome-lint` fails with two `remark-lint:awesome-github` errors unless the repository carries the GitHub topics `awesome` and `awesome-list` — the gate reads them from `origin`, so a local clone without a remote reports "must reside in a valid git repository" instead, which is an environment artefact, not a README defect. Set once on the published repository on 2026-10-17: `awesome`, `awesome-list`, `reverse-engineering`, `decompilation`, `reimplementation` (`gh repo edit {owner}/{repo} --add-topic awesome --add-topic awesome-list`, read back with `gh api repos/{owner}/{repo}/topics --jq .names`).
- `--apply` rewrites `★ <n>`, `<n> forks` / `<n> fork` (English) and `<n> fork` (Chinese), and `pushed <date>` / `last push <date>` / `推送于` / `最近推送`, then the `Data last refreshed <date>` / `数据刷新于 <date>` line. It only ever touches lines starting with `- [owner/repo](https://github.com/…)` plus that date line: `created <date>` (historical fact), `⚠` prose and every description are left alone, and prose that mentions a number in another shape (`3★`, `5★`, `76 .nls`) is not a patch target.
- It never *adds* a missing token. An entry without `★` stays without one — adding one is a human editorial act.
- Numbers must always equal the newest snapshot. If a refresh was partial, fix the numbers by finishing the run, not by editing the date line by hand.
- `scripts/snapshot-<date>.tsv` is gitignored: it is local/CI evidence, and one file per day is not something to commit.
- With `GITHUB_TOKEN` or `GH_TOKEN` in the environment the script authenticates and stops throttling. Unauthenticated it sleeps 7 s per call, and a full pass (134 measured slugs) will **not** fit in the 60 req/h anonymous budget — expect `MISSING` lines for the tail, which is a quota artefact, not a dead project. Locally, `GITHUB_TOKEN=$(gh auth token) python3 scripts/verify.py refresh --apply` is the way to get a complete pass.
- `.github/workflows/refresh.yml` (cron `17 6 * * *` + `workflow_dispatch`) runs `refresh --apply` with the workflow's own `GITHUB_TOKEN`, then gates on `check-i18n.py` and `awesome-lint`, reports `verify.py links` without gating, and opens a PR on branch `data/refresh` **only when the patch actually changed something**. `.github/workflows/lint.yml` gates structure and the mirror on every push and PR. Auto-commits to `main` are deliberately not used — a refresh is reviewed before it lands.

## Language mirror

`README.md` is English; `README.zh-CN.md` is a full mirror — same sections, same entries, same numbers, same `⚠` marks, in that order. `scripts/check-i18n.py` enforces it: identical link set both ways, identical heading list and heading order (**level 2 and level 3 both**, so a `Games` platform subsection has to exist on both sides with the same entry count), identical entry count per heading, identical `⚠` count. It counts as an entry only a bullet whose link is an `http(s)` URL, so `Contents` sub-items are not mistaken for entries. Change both in one commit, or state in the PR which one was touched. Translation keeps the original product names where no established Chinese title exists; do not invent Chinese titles for game names.
